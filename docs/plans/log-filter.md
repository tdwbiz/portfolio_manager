# Plan: log filter and safe file names (phase 2 step 11; audit 4 batches C + D)

## Goal

Nothing that leaves the app in text form — log lines, JSON import logs, moved/processed file names, stored `file_name` rows, error messages — contains a real account number or its last 4 digits.

Three pieces:

1. A `logging.Filter` built on `scrub_text` (fingerprint match → account **name**, exactly-15-digit runs → `BANK_ACCOUNT`, dates/amounts untouched because only exact fingerprint matches are replaced), attached to the app's log handlers — including the `imports.duplicates` file logger — and the JSON import logs scrubbed at write time (they are `json.dump` writes, not `logging` records, so "attached to the JSON import log" is implemented as payload scrubbing in step 5). The filter **does not fail open**: when the name map cannot be built it still scrubs digit runs (see Decisions 6).
2. Fix the remaining call sites that put the parsed number into a log line, a result record or an error message: `imports/auto_import.py` (the `imports.duplicates` line and the two `'account': normalized_id` result records — currently lines 200, 207, 246; the task's 189/196/235 predate the scrub step) and `core/management/commands/manage_inbox_import.py` (the `Cannot resolve account for account_number=…` error — currently line 424, the task's 415).
3. Safe file names: files moved to `processed/` / `processed/errors/` at import get `<date>_<type>_<ACCOUNT_NAME>_<hash8>.<ext>` (audit 4 batch D, Q4 decision: the **name**, not even last-4), and a one-off management command rewrites the stored `RbcMonthly.file_name` / `RbcAnnual.file_name` values (which today mostly carry a last-4 like `-9999`) to the same pattern. The command has a `--dry-run` that prints **counts only**; tdw runs it on mercury after a backup.

`scrub_text(text, name_map)` in `core/utils/account_fingerprint.py` already does the replacement and requires the `name_map` (`build_fingerprint_name_map()`); this plan only consumes it.

## What changes

- `core/utils/safe_names.py` (new):
  - `hash8_of(data_or_path)` — first 8 hex chars of SHA-256 of the **file content** (bytes, or a path read in chunks). Not of the file *name*: the original name carries the account number and a hash of it could be brute-forced (Decision 1).
  - `safe_file_name(original_name, account_name, kind, *, date=None, hash8)` → `2026-10-31_monthly_TOM_TFSA_a1b2c3d4.pdf` / `2026_annual_TOM_TFSA_a1b2c3d4.pdf`. `original_name` contributes only the extension; the account name is upper-cased with non-alphanumerics → `_`; kinds: `monthly` (date = `YYYY-MM-DD`), `annual` (date = `YYYY`), and `unknown` (date = today) for PDFs that cannot be attributed to an account — those use `UNKNOWN_ACCOUNT` as the name part. `hash8` is required (raise if missing).
  - `is_safe_file_name(name)` — strict pattern check (kind/date consistency); used for idempotency (a safe name is stable: same inputs → same name).
- `core/utils/log_filter.py` (new) — `ScrubFilter(logging.Filter)`:
  - Caches `build_fingerprint_name_map()` with a **fixed 300-second TTL in code** (Decision 5: no env setting); class-level cache plus a `reset_cache()` for tests.
  - Rewrites `record.msg = scrub_text(record.getMessage(), name_map)[0]` and clears `record.args` when anything changed; non-string/empty messages are left alone.
  - **Does not fail open** (Decision 6): if the name map cannot be built (no DB, query error) or `scrub_text` raises (missing/short fingerprint key), it falls back to replacing every run of exactly 15 digits with `BANK_ACCOUNT` and every remaining run of ≥ 8 digits with `ACCOUNT`. It never raises inside `logging` (catch-all, always returns True).
- `portfolio_manager/settings.py` — `LOGGING`: add `filters: {"scrub": {"()": "core.utils.log_filter.ScrubFilter"}}` and `"filters": ["scrub"]` on the `console` and `file` handlers (covers every app logger via the root handlers; `settings_test.py` inherits `LOGGING` — no change there).
- `imports/auto_import.py` — attach `ScrubFilter()` to the `imports.duplicates` handler(s) in `_setup_duplicate_logger()` (the `FileHandler` and the PermissionError console fallback); replace `normalized_id` with the account **name** (fallback `UNKNOWN_ACCOUNT`) in the dup-logger line (~line 200) and in the two result records `'account': normalized_id` (~lines 207, 246). `normalized_id` stays as the `compute_tx_hash` input.
- `core/admin.py` — `BrokerStatementAdmin`: remove `raw_filename` from `list_display` and `search_fields` (Decision 4; docs/architecture.md wins over audit 4 Q3: admin shows name and last 4, never numbers).
- `core/management/commands/manage_inbox_import.py` — error message without the number (`Cannot resolve account for the parsed account number (UNKNOWN_ACCOUNT)`); the three stdout progress/dry-run lines that print `account_number` (lines ~278, ~406, ~514) use `account.name` (Decision 3; in dry-run mode the account is resolved read-only via `lookup_account`, fallback `UNKNOWN_ACCOUNT`); safe file names everywhere: compute the safe name once per PDF after the account is resolved (`hash8_of` on the file content), and use it for the `processed/`/`errors/` move, the JSON log stem (`+_ERROR` when errors), the `'filename'` field, `RbcMonthly`/`RbcAnnual.file_name`, `_log_import`, the monthly duplicate check, and the stdout lines; PDFs that cannot be attributed to an account (unknown type, unresolvable number) get `<date>_<type>_UNKNOWN_ACCOUNT_<hash8>.<ext>`; JSON payload = `json.dumps(...)` run through `scrub_text` with the already-built `name_map` before writing (kills `account_number` in the VL payload); the `[i/total]` progress line and the `_move_file` log lines no longer print the original file name (hash8 / destination name instead).
- `core/management/commands/scrub_statement_file_names.py` (new) — one-off rewrite of `RbcMonthly.file_name` and `RbcAnnual.file_name` to the safe pattern using each row's `account.name`, `statement_date` / `report_year` and the content `hash8` of the physical file located by its stored name in `processed/` or `processed/errors/` (Decision 2: DB only, never renames on disk); rows whose source file is missing are skipped and counted; skips rows already matching `is_safe_file_name`; `--dry-run` prints counts only (per model: to-rename / already safe / missing source), never names or numbers.
- Tests: `core/tests/test_safe_names.py`, `core/tests/test_log_filter.py`, `core/tests/test_scrub_statement_file_names.py` (new); `imports/tests/test_manage_inbox_import.py` (new — mocked classifier/VL parser, fake PDF, asserts no digit run of the fake number appears in any produced file name or JSON file); updates in `imports/tests/` for the call-site and rename changes.

**No migrations** — no model changes (Decision 1).

## Stop conditions

- Stop if the monthly/annual **duplicate check** (keyed on `account + statement_date + currency + file_name`) stops recognising a re-import after step 5 — the safe name must stay a deterministic function of the original file **content** (+ account name + date); if it can't, ask before changing the dedupe key. Rows created before this change keep their old names until tdw runs `scrub_statement_file_names` on mercury; that is expected, not a stop.
- Stop if anything else parses `RbcMonthly.file_name` / `RbcAnnual.file_name` back into an account or date (`rg -n "file_name" imports core` first; `merge_duplicate_accounts.py:134` copies it — verify it just copies).
- Stop if the filter raises inside `logging` (recursion, `raiseExceptions` noise) or if scrubbing every record measurably slows imports — then narrow to per-logger filters and revise the plan.
- Stop if a step seems to need a **model change** (e.g. an `original_filename` column) — that is a plan revision, not an implementation detail.
- Never print or paste real numbers, `.env`, logs or `docs/reconciliation/` content while testing.

## Decisions (tdw, Oct 25)

1. **No `original_filename` column** — agreed. But `hash8` must not be a plain hash of the original file name (it contains the number and could be brute-forced): use the first 8 characters of SHA-256 of the **file content**. The scrub command locates the physical file by its stored name to compute it; rows whose source file is missing are skipped and counted.
2. **DB only** — agreed; the command never renames files on disk.
3. **The three stdout lines print the parsed number** — agreed, fix them in step 4.
4. **CSV rename deferred** to a follow-up branch — agreed. Audit 4 Q3 is superseded: `docs/architecture.md` wins (admin shows name and last 4, never numbers), so this branch removes `BrokerStatement.raw_filename` from the admin `list_display` and `search_fields` (step 4).
5. **No env setting** for the filter cache — a fixed 300 seconds in the code.
6. **The filter must not fail open**: if the name map cannot be built, it still replaces every run of ≥ 8 digits with `ACCOUNT` and every run of 15 digits with `BANK_ACCOUNT`, and it never raises inside logging.
7. **Step 3 blocker — filter module location (tdw):** `settings.LOGGING` is configured by `django.setup()` before the app registry is populated, so pointing it at `core.utils.log_filter.ScrubFilter` would import the heavy `core/utils/__init__.py` re-export package (and transitively Django models) too early. Fix: move `ScrubFilter` to **`core/log_filter.py`** (stdlib-only at module import time), import the `account_fingerprint` helpers (`build_fingerprint_name_map`, `scrub_text`) lazily inside its methods, point `LOGGING` at `core.log_filter.ScrubFilter`, and update the test patch target. Do **not** change `core/utils/__init__.py`. Also add a **re-entry guard** (thread-local flag): log records produced while the filter is building the name map on the same thread (e.g. SQL query logging) get the fallback scrub instead of recursing into another build — covered by a unit test. This overrides the `core/utils/log_filter.py` references in "What changes" and steps 2–3.
8. **JSON payload scrub for unresolvable numbers (tdw):** `scrub_text` leaves unmatched candidates untouched, so a parsed `account_number` with no stored fingerprint would survive into the JSON log payload (pre-existing gap; step 5's scrub alone does not close it). Fix: before dumping, for every parsed account number (each monthly section's `account_number` and the annual data's), set the field to the account **name** if its fingerprint is in `name_map`, otherwise to `UNKNOWN_ACCOUNT`; then also replace every other occurrence of that same parsed value in the payload — both as parsed and in its normalized form — with the same label, so a number repeated in a description or raw text field cannot survive. No general digit scrub of the payload (`scrub_text` + 15-digit bank runs are still applied). Covered by tests including an annual PDF case.
9. **Consultant review fixes (tdw) — three one-commit fixes, nothing else changed:**
   - **(a) `imports/auto_import.py`** — the `imports.duplicates` line lost the comma after the account name when step 4 swapped `normalized_id` for the name (the line ended `{account.name}` where it used to end `{normalized_id},`), so the name and the date merged into one field and every later column of `CSV_Duplicates.csv` shifted. Restored the comma; test asserts a duplicate line has exactly 11 columns (matching the header) and that the account column is the account name.
   - **(b) `ScrubFilter`** — it only scrubbed `record.getMessage()`, so exception tracebacks (`logger.exception` / `exc_info=True`) and `stack_info` reached the handlers unscrubbed. Now, when `record.exc_info` is set, it is formatted with `logging.Formatter().formatException`, scrubbed the same way as the message and stored in `record.exc_text` (handlers emit a pre-set `exc_text` verbatim); `record.stack_info` is scrubbed too; the filter still never raises. Test: an exception whose message contains the fake number `90000001` comes out of `exc_text` as `ACCOUNT_A`.
   - **(c) `manage_inbox_import.py`** — a monthly section without a usable statement date (missing, or truthy but malformed so it failed `safe_file_name`'s YYYY-MM-DD check) made `safe_file_name` raise `ValueError` and stop the whole run. The section's date is now coerced up front (`_coerce_statement_date` → `datetime.date` or `None`); a section with no usable date is skipped for storage as before, and when no other section yields an attributable name the PDF gets the unattributable `UNKNOWN_ACCOUNT` unknown-pattern name. Tests for both a missing and a malformed statement date.
